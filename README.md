# Codex 额度看护

Windows 本地看护，程序目录为 `D:\app date\codex project\codex看护软件`，桌面入口为“Codex 额度看护”。2026-10-10 从 C 盘迁移到此目录。已移除 AI helper 启动脚本、调用链和配置读取，不再启动 Claude Code、DeepSeek 或其他 AI 诊断进程。历史报告、日志和备份保留供人工复核，不再执行。

## 从仓库使用

这是基于 PowerShell 的 Windows 本地工具，需要本机已安装并运行 Codex 桌面与 Codex Switch。双击 `start.cmd` 打开托盘界面，或通过 `start-console.cmd` 打开控制台菜单；首次使用可先选演习模式。

`rules.json` 保存可编辑规则。迁移到其他电脑时，请检查其中的 `DesktopCallerThreadId`（本机 Codex 聊天 ID）、`ExpectedAccounts` 和 `QuotaSchedulerScript`（本机脚本路径），按实际环境配置。

仓库包含当前源码、规则、使用说明和自动测试。`state/`、`logs/`、`backups/`、`patches/` 以及旧压缩包和 `.bak-*` 文件通过 `.gitignore` 排除，仍保留在本机。运行状态不随 Git 同步；迁移正在使用的程序时，应单独保留 `state/` 中的去重记录及批次回执。

## 启动与界面

打开 Codex Switch 和 Codex 桌面，双击桌面“Codex 额度看护”，选择 **2 正常模式**。选 1 是演习，不切号、不发继续、不消耗额度。关闭终端不停止后台；双击托盘恢复同一轮日志。P 暂停/恢复，S 停止并回菜单，Q/ESC 收回托盘。

每轮处理后等待 3 秒再检查，实际间隔包含接口耗时。计时、当前账号五小时/周剩余额度在一行原地刷新，不写日常轮询日志。事件只报告重要变化。新运行建立独立 events 日志，关闭重开窗口保留本轮日志。

## 异常暂停与人工处理

规则无法处理的情况立即中止本轮后续动作、记录现场、进入异常暂停。包括未知程序/会话错误、切号结果未确认、续跑结果不确定、批量消耗没有成功回执、账号集合变化、已知恢复达到上限等。

- `state/manual-pause.json` 保存暂停状态，重启看护后仍暂停。
- `state/incidents/<报告ID>.json` 保存独立报告：时间、原因、错误详情、调用栈、账号/会话快照及去重/待处理状态。
- `state/last-report.json` 指向最新报告内容；`logs/watch.log` 保存完整诊断，`logs/events-*.log` 提示暂停原因和报告路径。
- 暂停期间不轮询账号、不切号、不消耗额度、不发送继续。它不会终止已经运行中的 Codex 工作对话。
- 处理后在窗口按 **P** 才恢复。同一个问题未解决会再次暂停并保存新报告。仅打开窗口、重启或普通按键不会解除异常暂停。
- 恢复不会删除去重记录，也不会重发结果不确定的请求。

正常的额度等待、主动关闭桌面、短暂网络故障等已知情况仍按规则等待或有限恢复。未知错误第一次出现即暂停；账号数据持续异常 5 分钟、桌面读取持续超时 3 分钟等达到既有恢复界限后也暂停。桌面配置明确拒绝续跑时保留延期重试，第 8 次拒绝仍未就绪则暂停。

演习的暂停状态使用 `manual-pause.dry-run.json`，不会覆盖正式暂停状态。极端情况下若状态目录不可写，程序会报告保存失败并在当前进程保持暂停；无法保证未能写盘的暂停跨重启恢复。

## 选号与继续

生产入口为 `codex-autopilot.ps1` → `lib/engine-v2.ps1`；异常暂停由 `lib/manual-pause.ps1` 负责。旧函数与 CLI runner 仅保留给历史兼容回归，生产不使用外部 exec resume。

有可用账号时，当前账号五小时或周额度耗尽就选择可切账号中周剩余额度最高者，五小时剩余作同分排序。切号前保存意图，切号后重新读取 active 账号确认。其他对话仍在运行或等待批准时延后切号，避免重启打断任务。

仅对最近五条本地桌面对话中额度墙、明确可恢复故障或明确尚未完成的工作发送继续。已完成、正在运行、有意等待以及无故障证据的已停止回合不发送。列表故障时使用本地元数据发现会话身份，再通过桌面逐条核实；不根据文件静默时间猜测任务已停止。

2026-10-08 修复：桌面可能把丢失运行进程的未完成回合显示为 interrupted，且 error 为空。现在核对同一会话、同一回合的原始记录：最新标记仍为 task_started、没有结束或 final 答复，才按中断恢复；turn_aborted、回合不匹配、文件缺失或未完整写入均不据此恢复。发送前再核对一次，仍使用原有额度验证与去重。证据按文件长度/修改时间缓存，判定原因写入 last-observation.json 的 Reason。此修复已做真实历史文件回放和隔离双对话续跑测试，不能等同于新的真实切号端到端验收。

切号确认后缓冲 **10 秒**，再核实会话与当前额度并尝试继续。若桌面明确返回 execution-config-loading，前三次拒绝各延期 10 秒；持续拒绝后每次延期至少 60 秒，第八次拒绝暂停并记录报告。重试前再次确认原回合仍需继续，运行中、用户新回合、额度未知或归零均不继续发送。缓冲和重试截止时间落盘，重启后接着处理。响应丢失等结果不确定的情况仍暂停，不盲目重发。`handled.json` 和 deliveries 跨重启保留。

2026-10-10 提速：切号指令成功返回后立即检查 active 账号，未切到目标时每秒复查，最多确认 60 秒。每轮先读取当前会话快照，再复用快照核对续跑结果；早已被用户/新回合替代且超过 120 秒确认窗口的历史发送记录不再每轮查询，原记录及去重保留。额度墙仍按实际账号归零或明确回合额度错误判断，其他工作运行/等待批准时仍延后切号。正常轮询间隔仍为 3 秒，实际响应时间取决于本地接口耗时；普通非额度中断仍保留原有静默保护。

## 全部不可用与批量计时

仅当所有账号均不可用才进入等待。默认 `ResetWaitPolicy=weekly-eligible`：排除周额度为 0 的账号，等待其余周额度仍大于 0 的账号五小时额度全部恢复；若全部周额度都为 0，则继续等待周额度恢复。

到齐后，`quota-batch.ps1` 在执行前复查账号，通过本地 `consume_account_quota` 接口对可用账号各尝试一次。无额度的账号跳过。至少一个账号消耗成功、仍有额度且五小时计时有效，就恢复选号和续跑。请求状态逐账号落盘，未知结果不重试；已成功批次不因重启再次消耗。

用户保留的 Windows 07:50 固定额度任务独立运行，不受看护暂停和批次去重控制；本次未修改该任务。
