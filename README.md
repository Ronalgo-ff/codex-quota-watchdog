# Codex 额度看护

Windows 本地看护，自动读取 Codex Switch 账号额度，按规则切号并恢复中断的 Codex 桌面聊天。双击 `start.cmd` 或桌面“Codex 额度看护”即可打开菜单。无法处理的异常会保存报告并暂停。

**第一次在新电脑使用：请先阅读 [新电脑配置指南](新电脑配置指南.md)。** 可以直接把本仓库链接交给你的 AI，让它按指南完成下载、环境检查、本机初始化和演习验证。通常无需手工修改源码，也不需要另外安装旧额度定时软件。

## 从仓库使用

这是基于 PowerShell 的 Windows 本地工具，需要 Windows PowerShell 5.1 或 PowerShell 7，以及已运行的 Codex 桌面与 Codex Switch；不需要 Node、npm、Python 或额外 AI CLI。Switch 使用官方登录即可，在“设置 → 网络与同步”启用“网页版监听端口”（默认 18080，建议仅限本机）。这项设置与顶部的模型代理开关相互独立。

首次启动会自动检查接口、发现本机 Codex 会话目录、记录账号数量并验证桌面聊天通道，生成被 Git 忽略的 `rules.local.json`。日常规则在 `rules.json`，本机配置优先。只检查环境可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File setup.ps1 -CheckOnly`；创建桌面快捷方式可运行同一命令去掉 `-CheckOnly`。账号数量改变后，确认是有意添加/删除，再运行 `setup.ps1 -RefreshAccounts` 更新基准。

双击 `start.cmd` 打开统一图形窗口（看护、额度定时两个页面），关闭窗口后留在托盘；`start-console.cmd` 保留控制台备用入口。首次使用可先选演习模式。启动失败会显示具体原因，记录在 `logs/startup.log`。PowerShell 7 请求本地接口时显式绕过环境代理，保留其他程序的代理设置。

托盘通过 Windows 按需任务独立启动，避免 Codex 重启时清理它所启动的子进程。该任务没有每日或开机触发器，仍由双击入口启动。看护、界面和切号后的补启动进程均由独立宿主管理。

切号前保存正在使用的 Codex 桌面路径和启动参数。切号后同时核实桌面进程及聊天通道；若桌面没有回来，等待 15 秒后按原启动方式补启动一次。补启动意图落盘，重启不重复执行；90 秒仍没有桌面进程则保存报告并暂停。已有桌面或未发生自动切号时不会补启动。

Switch 可能已切换账号，却在重开桌面时返回失败。看护会只读核实目标账号，不重复切号；目标已生效才进入桌面恢复流程。未知切号记录若超过原确认窗口，且桌面可读取、当前已是原账号和目标之外的第三个可用账号，会再次读取完整账号列表确认，然后把旧请求保存在 `handled.json` 的 `switchHistory` 中标为 `superseded`。这不代表旧目标切号成功；原始请求、去重及回执保留。仍是原账号、数据不完整或结果继续变化时保持保护，不自动重放。

仓库包含当前源码、规则、使用说明和自动测试。`state/`、`logs/`、`backups/`、`patches/` 以及旧压缩包和 `.bak-*` 文件通过 `.gitignore` 排除，仍保留在本机。运行状态不随 Git 同步；迁移正在使用的程序时，应单独保留 `state/` 中的去重记录及批次回执。

## 启动与界面

打开 Codex Switch 和 Codex 桌面，双击桌面“Codex 额度看护”，在“看护”页选择 **2 正常模式**。选 1 是演习，不切号、不发继续、不消耗额度。界面提供暂停/恢复和停止按钮。关闭窗口不停止后台；双击托盘恢复同一次运行的界面和最新重要事件。首次打开不会自动启动看护。

每轮处理后等待 3 秒再检查，实际间隔包含接口耗时。图形界面原地刷新计时与当前账号五小时/周剩余额度，另展示全部账号；界面读取账号为独立异步只读请求，不阻塞界面或启动切号。事件只报告重要变化。新运行建立独立 events 日志，关闭重开窗口保留本轮日志。控制台备用入口继续支持原有快捷键。

## 异常暂停与人工处理

无法确认动作结果或规则无法处理的情况会中止本轮后续动作、记录现场、进入异常暂停。包括未知程序/会话错误、切号结果未确认、续跑结果不确定、批量消耗没有成功回执、账号集合变化等。已识别的单聊天故障按下述规则单独处理。

- `state/manual-pause.json` 保存暂停状态，重启看护后仍暂停。
- `state/incidents/<报告ID>.json` 保存独立报告：时间、原因、错误详情、调用栈、账号/会话快照及去重/待处理状态。
- `state/last-report.json` 指向最新报告内容；`logs/watch.log` 保存完整诊断，`logs/events-*.log` 提示暂停原因和报告路径。
- 暂停期间不轮询账号、不切号、不消耗额度、不发送继续。它不会终止已经运行中的 Codex 工作对话。
- 处理后点击 **恢复看护** 才恢复，控制台备用入口仍可按 P。同一个问题未解决会再次暂停并保存新报告。仅打开窗口或重启不会解除异常暂停。
- 恢复不会删除去重记录，也不会重发结果不确定的请求。

正常的额度等待、主动关闭桌面、桌面只读接口超时或短暂网络故障，会继续等待并自动重连；读取不完整期间不切号、不发送继续。失效的桌面通道暂时避开 30 秒，后续操作重新发现可用通道；不重复发送结果不确定的请求。最近 12 小时没有本地记录时，仍可通过缓存的聊天身份逐条核实安全状态，旧聊天不会因此重新续跑。界面读取状态快照允许原子替换，短暂文件占用有有限重试。

桌面通道发现同时支持新版 `codex-app-tools-*` 与旧版 `codex-browser-use-*`，并核实接口提供所需的聊天工具。浏览器专用通道不作为聊天通道；不依赖从 Codex 继承环境变量，托盘独立启动时也会自动发现。

未知错误第一次出现仍暂停；账号数量持续不符 5 分钟、发送或消耗结果不确定、切号后无法核实账号等，需要人工检查。当前账号暂缺、出现多个当前账号或额度暂不可读时停止本轮动作并继续只读检查，数据完整后自动恢复。账号数量异常的五分钟计时只累计连续异常，其他接口故障不会沿用旧计时。

2026-10-18 修复：聊天回合返回 401/403、登录失效或授权失败时，只停止该回合的自动续跑；其他聊天与额度看护继续。网络错误达到自动续跑上限，以及桌面配置连续八次明确拒绝续跑，也只阻止对应回合。`state/incidents/thread-*.json` 保存原始错误，`handled.json` 的 `threadIssues` 跨重启去重，同一故障不反复写报告。第八次配置拒绝写为 `blocked`，重启不会发送第九次；用户检查问题并开始新回合后，按新回合重新判断。报告不会把未确认的发送标为成功，也不会自动重放旧请求。登录或工作区权限本身需要在 Codex 中处理，看护不能代替服务端授权。

演习的暂停状态使用 `manual-pause.dry-run.json`，不会覆盖正式暂停状态。极端情况下若状态目录不可写，程序会报告保存失败并在当前进程保持暂停；无法保证未能写盘的暂停跨重启恢复。

## 选号与继续

生产入口为 `codex-autopilot.ps1` → `lib/engine-v2.ps1`；异常暂停由 `lib/manual-pause.ps1` 负责。旧函数与 CLI runner 仅保留给历史兼容回归，生产不使用外部 exec resume。

有可用账号时，当前账号五小时或周额度耗尽就选择可切账号中周剩余额度最高者，五小时剩余作同分排序。切号前保存意图，切号后重新读取 active 账号确认。其他对话仍在运行或等待批准时延后切号，避免重启打断任务。

仅对最近五条本地桌面对话中额度墙、明确可恢复故障或明确尚未完成的工作发送继续。已完成、正在运行、有意等待以及无故障证据的已停止回合不发送。列表故障时使用本地元数据发现会话身份，再通过桌面逐条核实；不根据文件静默时间猜测任务已停止。

2026-10-08 修复：桌面可能把丢失运行进程的未完成回合显示为 interrupted，且 error 为空。现在核对同一会话、同一回合的原始记录：最新标记仍为 task_started、没有结束或 final 答复，才按中断恢复；turn_aborted、回合不匹配、文件缺失或未完整写入均不据此恢复。发送前再核对一次，仍使用原有额度验证与去重。证据按文件长度/修改时间缓存，判定原因写入 last-observation.json 的 Reason。此修复已做真实历史文件回放和隔离双对话续跑测试，不能等同于新的真实切号端到端验收。

切号确认后缓冲 **10 秒**，再核实会话与当前额度并尝试继续。若桌面明确返回 execution-config-loading，前三次拒绝各延期 10 秒；持续拒绝后每次延期至少 60 秒，第八次拒绝停止该回合的重试并记录报告，其他看护继续。重试前再次确认原回合仍需继续，运行中、用户新回合、额度未知或归零均不继续发送。缓冲和重试截止时间落盘，重启后接着处理。响应丢失等结果不确定的情况仍暂停，不盲目重发。`handled.json` 和 deliveries 跨重启保留。

2026-10-10 提速：切号指令成功返回后立即检查 active 账号，未切到目标时每秒复查，最多确认 60 秒。每轮先读取当前会话快照，再复用快照核对续跑结果；早已被用户/新回合替代且超过 120 秒确认窗口的历史发送记录不再每轮查询，原记录及去重保留。额度墙仍按实际账号归零或明确回合额度错误判断，其他工作运行/等待批准时仍延后切号。正常轮询间隔仍为 3 秒，实际响应时间取决于本地接口耗时；普通非额度中断仍保留原有静默保护。

## 全部不可用与批量计时

仅当所有账号均不可用才进入等待。默认 `ResetWaitPolicy=weekly-eligible`：排除周额度为 0 的账号，等待其余周额度仍大于 0 的账号五小时额度全部恢复；若全部周额度都为 0，则继续等待周额度恢复。

到齐后，`quota-batch.ps1` 在执行前复查账号，通过本地 `consume_account_quota` 接口对可用账号各尝试一次。无额度的账号跳过。至少一个账号消耗成功、仍有额度且五小时计时有效，就恢复选号和续跑。请求状态逐账号落盘，未知结果不重试；已成功批次不因重启再次消耗。

## 额度定时（2026-10-12 合并）

“额度定时”页支持多个每日时间、端口设置、测试连接、保存并启用、停用定时、立即消耗一次和执行日志。立即消耗需要确认，会消耗真实额度；连接测试只读。长耗时操作交给独立后台进程，关闭窗口不终止它。

本机升级时读取到的实际设置是每天 **10:30**，保留该时间及 Windows 任务原有触发器、错过补执行、登录用户、唤醒等设置，只将执行入口改到项目内 scheduler.ps1。定时任务仍能在看护停止或暂停时独立运行，电脑需在原有登录环境中。

定时、手动与全空恢复使用共同 quota-batch.ps1。消耗前持有共享文件锁，避免重叠；同一刷新窗口在 120 秒内已有成功回执可直接复用。账号的消耗意图在 state/quota-coordination/accounts.json 落盘，未知结果跨来源、重启都不会重发，直到能够确认进入新的刷新窗口。批次回执继续保留在 state/quota-batches。定时设置 state/scheduler/config.json，执行日志 logs/scheduler.log，执行结果 state/scheduler/last-run.json。

升级前的本机适配、运行状态、旧定时配置和任务 XML 保存在项目 `backups/update-*`，可用于恢复。桌面“Codex 额度看护”使用项目 assets/codex-quota.ico 的盾牌时钟图标。桌面、窗口、托盘使用同一图标。

## 验证与维护

运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tests\run-all.ps1`。自动测试使用隔离目录及模拟接口，不消耗真实账号额度。入口测试使用真实隐藏 PowerShell 进程，验证首次异常暂停、重启持久化、手动恢复、暂停期间无后续操作和独占锁。

曾核实真实自动切号续跑及部分账号批量消耗成功；模拟通过不等于所有端到端场景均已验收。暂停隔离回归覆盖真实 401 错误结构、其他聊天继续、重启去重、配置重试上限、账号数据长时间不可读，以及未知发送结果仍暂停的保护。

不要删除 `state/handled.json` 或手工重放批次。旧自动诊断入口已移到 `backups/remove-helper-*` 的 `.disabled` 历史副本，现行代码不引用它们。此程序不再依赖本机 AI CLI，但不卸载你用于其他工作的 CLI 或其配置。
